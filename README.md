# OpenBareMap 2.0

OpenBareMap is an offline topographic map for hiking, available as separate regional versions for **Ireland**, **England & Wales (including the Isle of Man)**, **Scotland**, **Sierra Nevada, Spain**, **the Pyrenees (France, Spain & Andorra)**, **the Dolomites, Italy**, **the Faroe Islands**, **Southern, Central and Northern Norway**, the **Balearic Islands**, **Corsica**, **Sardinia**, **Sicily**, **Crete**, **Cyprus**, **Malta**, the **Canary Islands** and **Madeira**. Each edition has **20 m contours**, its own source coverage, map databases and platform packages. Mobile bundles are integration components for apps using MapLibre Native; Garmin downloads are display-only maps.

## Downloads and incorporation instructions

**All finished iOS, Android and Garmin downloads are hosted on Cloudflare R2, outside Git.** Use the direct links below; cloning this repository does not download these packages. See [file storage and restoration](#file-storage-and-restoration) for developer resources.

Each iOS download contains the complete regional resource bundle, Swift loader, example view controller, dependency information and instructions. Each Android download contains the complete importable map ZIP, loader AAR and Kotlin source, an example Activity, dependency information and instructions. Both include checksums, legends and attribution. Install the MapLibre renderer through the dependency instructions supplied with the bundle.

## The map

- Terrain: gently smoothed 20 m contours, 100 m index contours, hillshade, summit and saddle names, summit dots and cliff markings.
- Land cover: woodland, farmland, grass, heath, scrub, wetlands, textured bog, peat workings, rock, scree, sand and beaches.
- Transport: roads, bridges and tunnels, tracks, paths, footways, bridleways, cycleways, steps, walking/cycling routes, railways and ferries.
- Places and facilities: settlements, islands, water names, outdoor facilities, parking and regional labels.
- Offline resources: local databases, styles, fonts, sprites, legends and attribution notices.

Mobile and web maps share cartography. Garmin uses its native fonts, symbols, terrain presentation and detail levels. All Garmin editions use package **2.0.1-trail-detail-r1**: green paths, brown farm/forest tracks and red walking routes share 4-pixel dashed strokes, transparent gaps and one close-detail visibility threshold. Bridleways, cycleways, steps and cycling-route markings also appear only at this finest detail level. Buildings occupy only the finest stored detail level, with fine contours retained in the intervening view. Garmin settings determine the actual screen scale. The Garmin maps are display-only, with native elevation data and no turn-by-turn routing. [Earlier Garmin release files and checksums](garmin/releases/2.0.1-trail-detail-r1/manifest.json); [Norway South](distribution/app-bundles-v1/garmin/norway-south/manifest.json), [Central](distribution/app-bundles-v1/garmin/norway-central/manifest.json) and [North](distribution/app-bundles-v1/garmin/norway-north/manifest.json) have separate publication manifests. Regional filenames, unique identifiers and clipped backgrounds allow the Garmin maps to remain enabled together without covering neighbouring regions. Follow the linked generic installation instructions and the mapping product's manual.

The Faroe Islands iOS and Android integration kits are approximately **42 MB each**; its Garmin image is approximately **8 MB**. Its [release manifest](releases/faroe-islands/2.0.0/manifest.json), [automated validation](releases/faroe-islands/2.0.0/validation.json) and [browser review](regions/faroe-islands/visual-review.json) record the build. ## App integration

For iOS, add the full `OpenBareMap.bundle` as a resource and the supplied Swift loader to the application target, then load its resolved style using MapLibre. The kit includes a UIKit example suitable for adaptation to UIKit or SwiftUI. Use explicit Bundle URLs when an app contains multiple regions.

For Android, add the supplied loader AAR or Kotlin source and the documented renderer dependencies. Install the inner resource ZIP on a worker thread into persistent app-private storage, then load the resolved style on the main thread. The example includes MapView lifecycle handling, map import, legend and credits.

The bundles contain map data and integration support. The consuming app supplies its renderer dependency, interface, signing, distribution and any location features. Check resource integrity, rendering, memory use and offline behavior with the app's selected SDK and deployment targets. [Android integration](android/README.md) and [iOS integration](ios/README.md) describe the repository components.

## Source, export and local viewing

Git LFS stores many earlier source archives and selected map databases; finished release downloads are hosted on Cloudflare R2. Norway and Mediterranean island bulk inputs and databases are excluded from both Git and LFS. Check the [storage guide](#file-storage-and-restoration) before exporting or starting a local viewer: a fresh clone is not a complete map installation. Existing commands without a region argument select Ireland.

```sh
git lfs install --local
git lfs pull

# Separate resource exports; destinations must be new.
python3 ios/build_bundle.py --region scotland --output /absolute/new/scotland-ios
python3 android/build_package.py --region scotland --output /absolute/new/scotland-android

# Local viewers
python3 scripts/serve.py --region ireland --port 8765
python3 scripts/serve.py --region england-wales --port 8766
python3 scripts/serve.py --region scotland --port 8767
```

Use `ireland`, `england-wales`, `scotland`, `sierra-nevada`, `pyrenees`, `dolomites`, `faroe-islands`, `norway-south`, `norway-central`, `norway-north`, `balearic-islands`, `corsica`, `sardinia`, `sicily`, `crete`, `cyprus`, `malta`, `canary-islands` or `madeira` for the resource exporters. The three Norway editions are published; phone and Garmin downloads have passed full public checksum verification. Their [coverage plan](config/norway-editions.json) includes full-detail overlaps around Trondheim and Bodø. The versioned integration kits are assembled by `scripts/build_app_distribution.py`; [distribution packaging](distribution/README.md) describes their contents and storage. [Regional build reference](docs/regional-editions.md) covers sources and full map builds. The England/Wales basemap is stored as verified LFS parts and restored automatically when selected; allow space for the parts and reconstructed database.

Source completeness, geographic accuracy and readability depend on the input data and renderer. ## File storage and restoration

A Git clone contains the code, styles, configuration and release records. Large resources have three different storage arrangements:

| Resource | Where it lives | How to obtain it |
| --- | --- | --- |
| Finished iOS / Android kits and Garmin images — all ten editions | **Cloudflare R2; outside Git** | Use the download table above, or the verified restore commands below. |
| Most earlier source datasets and selected working databases | **Git LFS** | Run `git lfs pull` for the files required by your edition. England/Wales basemaps use tracked LFS parts, reassembled when selected. |
| Norway and Mediterranean island source extracts, elevation pixels, working databases and database parts | **Rebuildable local files; deliberately outside Git, LFS and Cloudflare backups** | Recreate when needed using the [regional build workflows](docs/regional-editions.md). Git retains configuration and provenance; Cloudflare retains finished downloads and previews. The restore command does not install working databases. |
| Dolomites and Faroe Islands selected contour databases | **Git LFS**, alongside their other selected databases | Fetch `releases/<region>/2.0.0/maps/topography-context.mbtiles` with `git lfs pull`. Unselected contour intermediates remain excluded. |
| Source locks, checksums, release manifests and Norway `.parts.json` records | **Ordinary Git** | Included in a clone. A checksum or parts manifest records a file; it does not contain its bytes. |

### Restore finished downloads from Cloudflare

The [R2 asset inventory](distribution/r2-assets.json) records **57 current delivery files, approximately 41.91 GB total**, with their public URLs, original local paths, exact sizes and SHA-256 checksums. The [app catalog](distribution/app-bundles-v1/catalog.json) also records platform instructions and map versions. These are delivery inventories, not a backup of every source or intermediate file.

```sh
# Inspect available files without downloading anything.
python3 scripts/restore_r2_assets.py --list

# Restore just one file to its recorded local path.
python3 scripts/restore_r2_assets.py --path regions/norway-south/garmin/dist/OpenBareMap-Norway-South.img

# Optional: restore all 57 delivery files (about 41.91 GB).
python3 scripts/restore_r2_assets.py --all
```

The restorer checks both size and SHA-256 and verifies existing files rather than replacing them. Some older phone bundles restore under `work/`, matching their catalog paths. Download only the platforms and regions you need; extraction requires additional disk space. To use an offline map, the direct download links are sufficient. To export or run a development preview, the relevant selected databases must also exist locally.

### Storage audit and maintenance

The [15 November 2026 audit](docs/storage-audit-2026-11-15.md) explains the Git / R2 split, missing restoration entries corrected in this update, and the deliberate Norway rebuild policy. Recommended maintenance: keep the delivery inventory synchronized with the app catalog and Garmin manifests, and label externally stored files explicitly. Norway and Mediterranean island working databases and source data are recreated when needed rather than archived in Git or Cloudflare; exact historical bulk bytes are not promised.

Removing a file from the current Git tree does not purge its historical LFS objects or reduce historical GitHub storage automatically.
