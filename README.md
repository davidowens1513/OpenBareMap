# OpenBareMap 2.0

OpenBareMap is an offline topographic map for hiking, available in **37 regional editions** across Europe, the Canadian Rockies and US national parks. Each edition has **20 m contours**, its own source coverage, map databases and platform packages. Mobile bundles are integration components for apps using MapLibre Native. Garmin downloads are display-only maps.

## Downloads and incorporation instructions

The [Apps by Onzy website](https://appsbyonzy.dev/) has its own [website repository](https://github.com/davidowens1513/AppsByOnzy-Website). Make homepage changes and publish the site from that checkout.

The [US National Parks build and release guide](docs/regional-editions.md#us-national-parks) covers nine editions, with Yellowstone and Grand Teton in a shared map.

The [Picos de Europa and High Tatras build and release guide](docs/regional-editions.md#picos-de-europa-and-high-tatras) covers the two separate mountain editions.

The [Canadian Rockies build and release guide](docs/regional-editions.md#canadian-rockies) covers the Banff, Jasper and Kananaskis–Waterton editions.

The [Iceland and Patagonia build and release guide](docs/regional-editions.md#iceland-and-patagonia) covers the Southern Highlands, Torres del Paine and El Chaltén.

The [permanent ice release guide](docs/regional-editions.md#permanent-ice-updates) records the glacier and permanent snowfield screening for all 37 editions, including the [Pyrenees 2.0.2 review](docs/regional-editions.md#pyrenees-ice-review). The [development history](docs/development-history.md#22-november-2026--glacier-and-snowfield-review) records the latest review and publication.

**The map downloads linked below are hosted on Cloudflare R2, outside Git.** Use the direct links below; cloning this repository does not download these packages. See [file storage and restoration](#file-storage-and-restoration) for developer resources.

Each iOS download contains the complete regional resource bundle, Swift loader, example view controller, dependency information and instructions. Each Android download contains the complete importable map ZIP, loader AAR and Kotlin source, an example Activity, dependency information and instructions. Both include checksums, legends and attribution. Install the MapLibre renderer through the dependency instructions supplied with the bundle.

## The map

- Terrain: gently smoothed 20 m contours, 100 m index contours, hillshade, summit and saddle names, summit dots and cliff markings.
- Land cover: woodland, farmland, grass, heath, scrub, wetlands, textured bog, peat workings, rock, scree, sand and beaches.
- Transport: roads, bridges and tunnels, tracks, paths, footways, bridleways, cycleways, steps, walking/cycling routes, railways and ferries.
- Places and facilities: settlements, islands, water names, outdoor facilities, parking and regional labels.
- Offline resources: local databases, styles, fonts, sprites, legends and attribution notices.

Mobile and web maps share cartography. Garmin uses its native fonts, symbols, terrain presentation and detail levels. All Garmin editions use package **2.0.1-trail-detail-r1**: green paths, brown farm/forest tracks and red walking routes share 4-pixel dashed strokes, transparent gaps and one close-detail visibility threshold. Bridleways, cycleways, steps and cycling-route markings also appear only at this finest detail level. Buildings occupy only the finest stored detail level, with fine contours retained in the intervening view. Garmin settings determine the actual screen scale. The Garmin maps are display-only, with native elevation data and no turn-by-turn routing. [Earlier Garmin release files and checksums](garmin/releases/2.0.1-trail-detail-r1/manifest.json); [Norway South](distribution/app-bundles-v1/garmin/norway-south/manifest.json), [Central](distribution/app-bundles-v1/garmin/norway-central/manifest.json) and [North](distribution/app-bundles-v1/garmin/norway-north/manifest.json) have separate publication manifests. Regional filenames, unique identifiers and clipped backgrounds allow the Garmin maps to remain enabled together without covering neighbouring regions. Follow the linked generic installation instructions and the mapping product's manual.

The Faroe Islands iOS and Android integration kits are approximately **42 MB each**; its Garmin image is approximately **8 MB**. ## App integration

For iOS, add the full `OpenBareMap.bundle` as a resource and the supplied Swift loader to the application target, then load its resolved style using MapLibre. The kit includes a UIKit example suitable for adaptation to UIKit or SwiftUI. Use explicit Bundle URLs when an app contains multiple regions.

For Android, add the supplied loader AAR or Kotlin source and the documented renderer dependencies. Install the inner resource ZIP on a worker thread into persistent app-private storage, then load the resolved style on the main thread. The example includes MapView lifecycle handling, map import, legend and credits.

The bundles contain map data and integration support. The consuming app supplies its renderer dependency, interface, signing, distribution and any location features. Check resource integrity, rendering, memory use and offline behavior with the app's selected SDK and deployment targets. [Android integration](android/README.md) and [iOS integration](ios/README.md) describe the repository components.

## Source, export and local viewing

Git LFS stores many earlier source archives and selected map databases; finished release downloads are hosted on Cloudflare R2. Alps, Norway and Mediterranean/Atlantic island bulk inputs and databases are excluded from both Git and LFS. Check the [storage guide](#file-storage-and-restoration) before exporting or starting a local viewer: a fresh clone is not a complete map installation. Existing commands without a region argument select Ireland.

```sh
git lfs install --local
git lfs pull

# Separate resource exports; destinations must be new.
python3 ios/build_bundle.py --region scotland --output /absolute/new/scotland-ios
python3 android/build_package.py --region scotland --output /absolute/new/scotland-android

# Local viewers
python3 scripts/serve.py --region ireland --port 8765
python3 scripts/serve.py --region england-wales --port 8766
python3 scripts/serve.py --region scotland --port 8767
```

Run a resource exporter with `--help` for its supported region IDs. The three Norway editions are published; phone and Garmin downloads have passed full public checksum verification. Their [coverage plan](config/norway-editions.json) includes full-detail overlaps around Trondheim and Bodø. The versioned integration kits are assembled by `scripts/build_app_distribution.py`; [distribution packaging](distribution/README.md) describes their contents and storage. [Regional build reference](docs/regional-editions.md) covers sources and full map builds. The England/Wales basemap is stored as verified LFS parts and restored automatically when selected; allow space for the parts and reconstructed database.

## Data and attribution

OpenStreetMap-derived data uses the [Open Database Licence](https://opendatacommons.org/licenses/odbl/1-0/) with [OpenStreetMap attribution](https://www.openstreetmap.org/copyright). Bundles include the applicable map, font and terrain notices. Sierra Nevada national park boundaries are credited to Organismo Autónomo Parques Nacionales (MITECO/OAPN), CC BY 4.0, with source details in the regional provenance. Consuming apps must make those notices accessible to users.

Elevation comes from approximately 30 m composite Terrain Tiles data, including Copernicus EU-DEM, USGS and NOAA sources. The Faroe Islands, Alps, Norway and Mediterranean/Atlantic island editions use Copernicus DEM GLO-30 Public with EGM2008 orthometric heights. The 20 m contour interval describes line spacing rather than terrain accuracy. [Terrain attribution](viewer/terrain-attribution.html) and the regional source locks identify the inputs.

Source completeness, geographic accuracy and readability depend on the input data and renderer. Cliff symbols are not certified as indicating the downhill side; access tags do not establish route suitability or access rights. Townland, grid and inherited font provenance is described in the source records.

## File storage and restoration

A Git clone contains the code, styles, configuration and release records. Large resources have three different storage arrangements:

| Resource | Where it lives | How to obtain it |
| --- | --- | --- |
| Finished iOS / Android kits and Garmin images | **Cloudflare R2; outside Git** | Use the download table above, or the verified restore commands below. |
| Most earlier source datasets and selected working databases | **Git LFS** | Run `git lfs pull` for the files required by your edition. England/Wales basemaps use tracked LFS parts, reassembled when selected. |
| Alps, Norway and Mediterranean/Atlantic island source extracts, elevation pixels, working databases and database parts | **Rebuildable local files; deliberately outside Git, LFS and Cloudflare backups** | Recreate when needed using the [regional build workflows](docs/regional-editions.md). Git retains configuration and provenance; Cloudflare retains finished downloads and previews. The restore command does not install working databases. |
| US National Parks OSM extracts, elevation tiles, working databases and generated Garmin geometry | **Rebuildable local files** | Use the [US National Parks workflow](docs/regional-editions.md#us-national-parks). Git records park coverage, source references and checksums. |
| Dolomites and Faroe Islands selected contour databases | **Git LFS**, alongside their other selected databases | Fetch `releases/<region>/2.0.0/maps/topography-context.mbtiles` with `git lfs pull`. Unselected contour intermediates remain excluded. |
| Source locks, checksums, release manifests and Norway `.parts.json` records | **Ordinary Git** | Included in a clone. A checksum or parts manifest records a file; it does not contain its bytes. |

### Restore finished downloads from Cloudflare

The [R2 asset inventory](distribution/r2-assets.json) records current delivery files with their public URLs, original local paths, exact sizes and SHA-256 checksums. The [app catalog](distribution/app-bundles-v1/catalog.json) also records platform instructions and map versions. The regional build workflows describe how to recreate source and intermediate files.

```sh
# Inspect available files without downloading anything.
python3 scripts/restore_r2_assets.py --list

# Restore just one file to its recorded local path.
python3 scripts/restore_r2_assets.py --path regions/norway-south/garmin/dist/OpenBareMap-Norway-South.img

# Optional: restore all delivery files.
python3 scripts/restore_r2_assets.py --all
```

The restorer checks both size and SHA-256 and verifies existing files rather than replacing them. Some older phone bundles restore under `work/`, matching their catalog paths. Download only the platforms and regions you need; extraction requires additional disk space. To use an offline map, the direct download links are sufficient. To export or run a development preview, the relevant selected databases must also exist locally.

### Storage audit and maintenance

The [15 November 2026 audit](docs/storage-audit-2026-11-15.md) explains the Git / R2 split, missing restoration entries corrected in this update, and the deliberate Norway rebuild policy. Recommended maintenance: keep the delivery inventory synchronized with the app catalog and Garmin manifests, and label externally stored files explicitly. Alps, Norway and Mediterranean/Atlantic island working databases and source data are recreated when needed rather than archived in Git or Cloudflare; exact historical bulk bytes are not promised.

Removing a file from the current Git tree does not purge its historical LFS objects or reduce historical GitHub storage automatically.
